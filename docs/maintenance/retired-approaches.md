# Retired-approach cleanup

## Scope

A read-only audit of the accepted baseline found no executable remnants of the
retired dictionary recall gate, body-preload API, standalone `Mnion.events`, or
withdrawn Hermes origin-attestation observer in product main. Do not delete live
capture matching/lifecycle events or Claude's separate devpane by name similarity.

The uncommitted, canceled observer worktree was preserved outside the active
product workspace with its base commit, exact file hashes and binary patches.
A disposable restoration checked original staged/combined diffs, status and all
changed/untracked files before removal. Full preservation evidence stays private;
this document does not publish that source or any real-memory corpus.

Clean, merged obsolete feature worktrees/local branches were also removed after
checking status, runtime path consumers and recoverable commits. Accepted history
and the separate private recall experiment remain available. The working local
Telegram observer is not the canceled recorder and remains untouched.

## Narrow product changes

- Remove unused `mnion.mcp_server.default_receipts_path` and
  `default_read_model_path` module helpers. No tracked consumers existed. Configure
  `create_server(state_dir=..., receipts_path=..., read_model_path=...)` instead;
  this does not change MCP tool names, path resolution or receipt semantics.
- Keep the tested state/ledger/call-state helpers and deliberately retained
  compatibility aliases. This is not a broad breaking-API cleanup.
- Make `NEXT_STEPS.md` the current capability/open-work entry. Preserve its exact
  earlier contents in `docs/history/initial-next-steps.md`.
- Mark old decision/graph sketches as historical where later contracts supersede
  them, rather than rewriting the original decision bodies.
- Update the placement note to the seven-tool product surface, explicit-read
  freshness repair and separate read-only spontaneous ingress.

No memory rewrite, forgetting subsystem, pointer redesign, host-config change,
new capture, automatic promotion or next functional slice is part of this cleanup.
