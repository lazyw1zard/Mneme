## First-person need

## Acceptance boundary

- Reuse authored MnionConnection and projected claims, never infer edges.
- At most one transient two-node/one-edge entrance; no stored arc/cluster object.
- Select an eligible connection touching an exact route explicitly present in
  the current cue before falling back to the latest projected authored receipt
  (descending seq). Stable bounded windows, not whole-graph ranking.
- why_visible is explicit_route_in_cue or recent_authored_connection. Neither
  claims semantic relevance, unresolvedness, event chronology or proven causality.
- Keep the existing topic fallback. No word gate, embeddings, LLM, rotation,
  durable read-state, body preload, receipt scans, new MCP or host core patch.
- Read only the existing index, use fixed small indexed ranges, do not repair.
  Missing/old/corrupt graph projection must not suppress the topic map or assert
  that no connections exist. Index availability is not source freshness proof.
- Render source/target direction, exact claims, connection id, bounded explicitly
  named summary preview and exact get_neighborhood/get_item affordances. All
  content remains data/not instructions and author interpretations/not proof.
- Default Hermes prefetch passes the cue only to extract literal exact routes;
  ordinary unrelated text never prevents the memory-state entrance.
- Verify isolated RED/GREEN, unchanged source state, bounded/locked behavior,
  full relevant suite and a true native provider smoke. Parent owns code; one
  bounded independent spec/quality review before main. Public fixtures neutral;
  real preview private. Update local observer without claiming index annotations
  were in the prompt. This is not a full situational or autonomous recall policy.
