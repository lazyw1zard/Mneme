# Широкий кандидатный сбор и вход ветки — план следующей пробы

> Реализация: основной автор органа пишет смысловые интерфейсы и код сам;
> независимые агенты выполняют read-only SPEC, затем QUALITY/security review.
> Это исключение из общего шаблона subagent-driven implementation.

**Статус:** предлагаемый следующий слайс; документ не означает готовый код,
разрешение на live ingress или принятую схему консолидации веток.

**Цель:** я встречаю автоматически доступную зацепку возможной истории,
раскрываю основания и выбранные оригиналы до окончательного решения о составе.

**Архитектура:** явный ограниченный экспорт items и authored connections →
независимые сигналы кандидатов → ограниченный граф от seed → адресуемый
предварительный вход → выбранное раскрытие. Авторская консолидация — следующий
отдельный проход; не обязательное условие существования входа.

**Стек:** Python stdlib, JSON, pytest. Без embeddings, сети, моделей и workers
в сборщике. Изолированная ветка `experiment/automatic-entry-candidates`.

## Что проверено перед планированием

- Production baseline `8c2cb8f` уже имеет optional relations и neighbors при
  micro-consolidation. Этот план не заменяет работающий путь записи мнионов.
- Экспериментальный `probe.py` использует окно тактов как обязательный фильтр,
  затем требует текстовое пересечение или общий исходный tag.
- `authored_relations` в его результате пуст, вход authored connections не принят.
- Группировка в `build()` требует complete-link; `resolve()` также ограничивает
  старую форму группы. Нельзя заменить только группировщик и забыть reader.
- Первый эксперимент проверил механику, но получил исторический false negative.
  Этот результат сохраняется как ограничение v1, не переписывается как успех v2.

## Видимый результат

Предварительная строка входа должна давать смысловую зацепку из существующих
claims, статус «кандидат» и точный маршрут. Не выдавать набор общих слов за
полноценное понимание истории и не сочинять агентный пересказ в скрипте.
При отсутствии claims честно доступен только route-only вход.

После открытия: ограниченный состав, направленные авторские отношения с их
основаниями, отдельно автоматические ассоциации и причины включения, свидетели
усечения. Затем — отдельно выбранные оригиналы. Полный корпус не загружается.
Это форма offline-пробы; доставка такой строки в host ingress ещё не внедрена.

## Задача 1. Зафиксировать новый контраст, не переписав v1

**Файлы:** создать `tests/test_broad_candidate_entry.py` и
`docs/experiments/automatic-entry-candidates/candidate_probe.py`.
Старые `probe.py`, fixture и исторические результаты остаются контрольной v1.

1. Написать нейтральные RED fixtures: непохожие тексты с authored relation;
   A→B→C без A→C; correction через большой/неизвестный временной разрыв;
   соседние по времени, но разные сюжеты; слабый мост между двумя историями.
2. Запустить целевой тест и убедиться, что он падает из-за отсутствия нового
   поведения, а не импорта случайной runtime-среды.
3. Зафиксировать ожидаемые inclusions и допустимые лишние candidates до настройки.
   Candidate recall и точность принятой ветки — разные измерения.

## Задача 2. Подать имеющиеся отношения и основания

**Файлы:** новый `candidate_probe.py`, новый целевой test-файл.

1. Принять отдельный явный список connections с exact endpoints, id, kind и
   исходным relation_summary; не восстанавливать их из лексического сходства.
2. Проверить уникальность, literal routes, наличие endpoints в выбранном scope,
   допустимые kinds и типы; malformed input отвергать до результата.
3. Authored relations проходят независимо от лексического порога и call window.
   Известная связь — свидетельство авторства отношения, не объективная истина.
4. Автоматические основания оставить отдельно: точный общий source tag,
   лексическое сходство; при наличии пригодных структурированных данных — точная
   предметная ссылка. Не добавлять ненадёжный универсальный regex-extractor
   произвольных файлов/проектов ради количества сигналов.
5. Время — контекст/ранжирование слабых кандидатов, не универсальное semantic veto.
   Один такт, общая сессия или валентность не создают смысловое отношение.
   Не изобретать отсутствующие provenance или журнал co-retrieval.

## Задача 3. Заменить требование клики ограниченным раскрытием от seed

**Файлы:** новый `candidate_probe.py`, новый целевой test-файл.

1. RED: кандидат может содержать цепочку/развилку и shared nodes без all-to-all.
2. Минимальный детерминированный обход: authored adjacency раньше inferred
   adjacency, stable exact-route tie-break. Не вводить числовые semantic weights.
3. Сохранить путь/основание включения каждого участника. Ограничить hops, members,
   examined edges и общий размер выдачи; параметры пробы не объявлять порогом
   зрелости энграммы. Конкретные значения зафиксировать перед RED, не подбирать
   под один исторический пример.
4. Слабый мост может предложить соседнюю историю, но не делает всю component
   одной принятой веткой. Показывать смешанный статус и предел раскрытия.
5. Не позволять плотным inferred edges молча вытеснять известную correction.
   Если authored neighborhood сам превышает бюджет, показать усечение, не обещать
   полноты. Проверить это на adversarial fixture.

## Задача 4. Вход существует до ревью

**Файлы:** новый `candidate_probe.py`, новый целевой test-файл.

1. RED: build без модели и без authored entrance порождает адресуемый candidate.
2. Взять узнаваемую подпись из исходных claims; связанное изменение показывать
   через имеющиеся relations, не авторский синтез от имени скрипта.
3. Связать seed-адрес с версией алгоритма, показать snapshot/fingerprint.
   При росте состава в совместимой карте прежний seed должен раскрываться;
   исчезнувший seed даёт exact not_found, не ближайшую похожую ветку.
4. Проверить build → serialize → open в свежем процессе, затем selected item.
   В карте нет полных summary/rationale; оригиналы возвращаются отдельно.
5. Проверить UTF-8 output bound включая LF, длинные claims/grounds, неверные и
   неоднозначные адреса, порядок входа и неизменность exported originals.
   Глобальная вечная идентичность веток остаётся вне этой offline-пробы.

## Задача 5. Сравнить с v1 и пройти независимые gates

**Файлы:** новые нейтральные fixtures рядом с экспериментом; отдельный результат
v2, не перезапись `RESULTS.md` первой пробы.

1. Изолировать HOME/XDG/MNEME/config для всего процесса, включая subprocesses.
2. Targeted: `uv run --with pytest pytest -q tests/test_broad_candidate_entry.py`.
3. Regression: `uv run --with pytest pytest -q` и `git diff --check`.
   Команды здесь запланированы, не выданы за выполненные результаты.
4. Раздельно измерить возврат known authored edges и новые автоматические
   ассоциации: наличие первых не доказывает качество вторых.
5. До сравнения зафиксировать несколько положительных и отрицательных примеров;
   если нужна личная история, использовать отдельно согласованный private corpus.
   Нейтральные fixtures остаются единственным публичным содержимым.
6. SPEC → QUALITY/security; исправленные блокеры превратить в RED-регрессии и
   отдать на повторный review. Сохранить verified slice в remote experiment branch.

## Дальше, но не в этом кодовом слайсе

- Отдельный authorial pass: открыть выбранные originals, оставить целиком/частично,
  разделить или отклонить состав, при необходимости уточнить вход. Не вводить
  обязательный новый review_branch MCP или семантический worker заранее.
- Выбрать минимальную persistence форму принятой ветки/указателя только после
  одной такой пробы. Не превращать её в обязательное новое тело-пересказ.
- Затем отдельно согласовать core/host интеграцию: лёгкая автоматически доступная
  зацепка → bounded disclosure → selected originals. Пока нет live prefetch writes.
- Содержательный полный вход не сводить к одному короткому claim; его точная
  форма и уместность показа остаются следующим вопросом, а не решены сборщиком.
- Reinforcement, forgetting, Dream, vector search, wake и export не входят.

## Граница завершения ближайшего слайса

На изолированном входе я могу встретить и повторно открыть candidate, который
не теряет доступные authored relations из-за слов/времени, допускает цепочку и
ветвление, честно показывает основания/неполноту и возвращает выбранные originals
без их изменения. Это ещё не доказанная семантическая ветка и не production ingress.
