# Проба: метапоинтер как карта входа, не большой мнион

## Принятое направление

Денис уточнил: основная функция — «я знаю, что я это знаю», без загрузки всей
памяти. Это карта входов, через которую агент выбирает трассу и открывает нужные
следы/события, а не обязательная сборка связанных объектов в единый рассказ.
Я убираю из этой пробы требование написать целостную историю или принять решение
об энграмме. Отдельная глубокая консолидация остаётся возможной поздней работой.

Экспериментальный код допустим до решения всей архитектуры. База: принятый и
проверенный в GitHub `8c2cb8f0e6961b03281fa612f2f6f38934dde659`. Работать на
`experiment/metapointer-entry-map`; изменения можно отменить обычным git revert
или не переносить в main. Git не откатывает внешний corpus/config: живые записи
в этой пробе не менять. Оригинальные семантические тела неприкосновенны.

## Агентный проход

1. Я замечаю компактный вход: узнаваемое знание и маршрут, не готовый пересказ.
2. Я выбираю нужную трассу; механизм раскрывает ограниченные узлы и отношения.
3. Если нужно основание, отдельно открываю выбранный оригинал через get_item.
4. Разные ветви остаются ветвями; связи не превращаются в обязательную хронологию,
   единое событие или команду дальнейшему поведению.

## Первая исполнимая проба

На нейтральных временных fixtures использовать уже существующие exact item /
connection / get_neighborhood пути. Представление входа в тесте — ручной эскиз,
не выбранная публичная схема и не доказательство автоматического формирования.

Проверить:
- неизменный компактный вход не содержит тел и сам не раскрывает граф;
- явное раскрытие собирает имеющиеся отношения и ветви без загрузки тел;
- последующее продолжение становится доступным по той же точке входа;
- один новый corrects может оказаться за границей лимита старых рёбер;
- выбор другой точной точки позволяет пройти по иной трассе без общего рассказа;
- receipts / original bodies остаются неизменными при чтении.

Выход пробы — воспроизводимые наблюдения и проблемы, не утверждение, что
метапоинтер реализован или вообще полезен в модели/нативном ingress.

## Следующие проверки по результату

На одной уже открытой реальной развилке про самонаписание/авторство повторить
проверку маршрутов без копирования частного корпуса в публичный репозиторий.
Полные личные материалы — только в проверенном private destination.

Развести изменение структуры и устаревание смыслового входа. Порог новизны и
замещение версий — гипотезы, не выбранные механизмы. Для bounded раскрытия
has_more свидетельствует об обрезке, а не гарантирует отсутствие невидимых
исправлений при false вне описанной области. Не добавлять lifecycle/веса/семантический
поиск или автоматическое переписывание входа заранее.
