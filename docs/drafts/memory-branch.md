# Memory branch — ветка памяти

Рабочий файл поэтапного согласования архитектуры Mneme. Это описание структуры,
не реализованный API и не разрешение начинать реализацию. После обсуждения
структур на эти файлы можно сослаться из общего плана; сейчас он не переписывается.

## Согласовано: название и назначение — пункт 1

**Название:** memory branch / ветка памяти.

**Определение:** ветка памяти — адресуемая связанная история мнионов,
представленная картой и обладающая общими свойствами внимания, без отдельного
семантического тела поверх участников.

Ветка повышает уровень абстракции для механизма внимания: позволяет обращаться
к связанному материалу как к функциональному целому, а затем раскрывать нужные
участки и исходные мнионы. Она не становится самостоятельной семантической
сущностью, новым мнионом или обязательным обобщённым пересказом.

Участники и отношения представлены в карте. Не требуется отдельно повторять
описание каждого участника в ещё одном теле ветки. Исходное содержание остаётся
в самих мнионах.

Карта-поинтер и общие свойства относятся к одной ветке, а не образуют новые
уровни памяти. Яркость, опыт обращений и состояние консолидации обсуждаются
как свойства; их точный состав и поведение этим пунктом ещё не утверждены.

## Что означает название

Branch подчёркивает развитие связанной истории, а не только группировку по
лексическому сходству. Аналогия с Git помогает понимать адресуемый вход в историю,
но не переносит автоматически Git-операции или устройство дерева в Mneme.

Ранее употреблявшиеся «компонента», «связка», memory bundle, memory cluster
и union были вариантами обсуждения, а не дополнительными выбранными структурами.
Исторические документы с прежними словами не переименовываются этим файлом.

## Предложения по именам интерфейса — ещё не утверждённый API

- `MemoryBranch` — возможное имя типа.
- `get_branch` — возможное действие открытия карты ветки и её свойств.
- `get_item` — существующий путь к отдельному мниону; этот файл его не меняет.

## Открыто: обсуждать по одному пункту

- Как обосновывается присоединение мниона к ветке и как она расширяется.
- Участие мниона в нескольких ветках и доступ к одиночкам.
- Состав свойств, определения значимости/яркости/обратной связи и их динамика.
- Условия предложения консолидации в энграмму и изменения режима после неё.
- Правила автоматической видимости, конкуренции входов и ручного доступа.
- Точный контракт карты, идентичности/изменений ветки и инструментов.

Эти вопросы не считаются решёнными из-за наличия названия или этого файла.
Новые решения добавляются сюда по мере согласования, без молчаливого принятия
ранее предложенных формул, порогов или схем.
