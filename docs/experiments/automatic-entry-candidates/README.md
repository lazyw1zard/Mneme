# Автоматический entry-кандидат — скриптовая проба

## Зачем я делаю эту пробу

Я должна встретить зацепку памяти, даже если заранее не решила создать вход.
Иначе забытый след не участвует ни в возвращении, ни в дальнейшей консолидации.
Денис предложил удерживать согласованную связанную ветку как энграмму: не новый
пересказ-объект, а функциональные отношения с моей историей; сохраняемый объект —
указатель. Возможный экспорт — представление этой формы, не её первичная онтология.

**Разрешённый шаг здесь:** без агента собрать ассоциации, карту и автоматически
адресуемые entry-кандидаты. **Открытые гипотезы:** критерий зрелости/сложности ветки,
более глубокая авторская консолидация, возможный Dream, экспорт согласованной
энграммы и опыт-зависимое усиление. Эта проба не выбирает их реализацию.

## Контракт и метод

`probe.py` — stdlib-only CLI, без сети, модели, демона и записи файлов. Нет
путей по умолчанию к живой памяти. Вход — явный JSON `{"items": [...]}` с
выбранными экспортированными `MnionItem`-подобными объектами: точный `review_id`,
исходный `mnion`, `grouped_ids` и `receipt.mneme_call_seq`. Отсутствующий такт
остаётся неизвестным. Исходные тела не изменяются и не включаются в карту.

Скрипт:

1. Проверяет точные адреса, уникальность, типы и предел выбранного входа.
2. Вычисляет TF-IDF/cosine по словам summary и claim как **одной** семье признаков.
   Это лексическое приближение, не понимание синонимов, не embeddings и не
   установление согласия. Общие RU/EN слова отфильтрованы; русский поддерживается,
   но морфология и перефразирование пока не решены.
3. Через индекс слов и источников находит пары с пересечением. Допускает связь
   лишь в заданном окне тактов консолидации и при достаточно сильном текстовом
   пересечении **или** точном общем исходном теге. Два условия — временная
   близость и текстовое/источниковое основание — не подменяются одной валентностью.
4. Каждому принятому ребру сохраняет отдельные компоненты основания: расстояние
   по тактам, текстовую близость, общие слова, точное происхождение. Это
   `association_candidate`, не `continues / corrects / follows_from`.
5. Ограничивает степень узлов и явно сообщает число отброшенных подходящих пар.
   На каждой seed-паре строит жадную complete-link группу: каждый добавленный
   участник должен быть связан с каждым уже включённым. Цепочка A—B—C без A—C
   не превращается в одну группу. Группы могут пересекаться.
6. Формирует entry-кандидат без ручного текста: общие слова и имеющиеся claims,
   точные маршруты раскрытия и детерминированные seed-адреса. Совпавшие группы
   объединяют seed-адреса как aliases; добавление участника не уничтожает прежний
   seed-вход, пока его ребро остаётся в выбранном графе.

Конфиг пробы: `--window-calls 40`, `--min-similarity 0.25`,
`--min-shared-terms 2`, `--max-neighbors 4`. Это **экспериментальные настраиваемые
параметры**, не согласованный порог зрелости и не изменение production config.
Неизвестные такты и внеоконные исторические следы не получают ассоциаций этим
локальным методом; это ограничение покрытия, а не доказательство отсутствия связи.

## Что такое результат

- `nodes`: точные маршруты, исходные claims и такты, без summary/rationale.
- `edges`: недирективные ассоциации с основаниями. Порядок endpoints технический,
  не направление события; `authored_relations` остаётся пустым.
  Слова-подсказки длиннее 64 символов отображаются сокращённо с хеш-суффиксом и
  `shared_terms_abbreviated=true`; сравнение выполняется по исходным словам,
  а не сокращениям. Исходный текст и точные адреса не сокращаются.
- `entries`: адресуемые кандидаты, не полноценные энграммы. Семантическая
  согласованность не проверена: даже противоположные выводы могут быть близки.
  При общем исходном теге, непохожем тексте и отсутствии claims cue может быть
  пустым: такой кандидат пока даёт только маршрут и основание происхождения,
  а не узнаваемую смысловую подпись.
- `coverage`: охват явного входа, неизвестные такты, ограничения степени,
  неполнота истории и жадного покрытия групп. Все максимальные клики не перечисляются.
  Поле `partial` означает только отбрасывание подходящих рёбер лимитом степени;
  оно не удостоверяет полноту истории или отсутствие пропусков из-за неизвестных
  тактов. Для этого отдельно показаны `history_complete` и `unknown_clock_items`.
- `input_fingerprint`: отпечаток используемых нормализованных признаков, не
  проверка неизменности исходных тел и не версия всей живой памяти.

Нет отдельного сохранённого тела энграммы, переписанных мнионов или обязательной
новой карточки от агента. JSON-карта — воспроизводимый артефакт пробы. В другом
процессе `open` раскрывает точный entry из этой карты, а `item` возвращает
выбранный оригинал из явного исходного экспорта. Это не живой MCP-инструмент и
не интеграция с текущим MemoryProvider.

Не гарантируется вечность seed-адреса: если исходное ребро исчезло из выбранной
карты из-за изменения корпуса, конфигурации или лимита, возвращается `not_found`,
не похожая ветка. Для будущего инкрементального графа ещё нужны решения о ревизии,
охвате старых следов и устойчивости веток; их нет в этой пробе.

## Запуск без зависимостей

Из корня репозитория (fixture — явно синтетический, нейтральный):

```sh
python3 docs/experiments/automatic-entry-candidates/probe.py build \
  docs/experiments/automatic-entry-candidates/fixture.json > /tmp/entry-map.json
python3 docs/experiments/automatic-entry-candidates/probe.py open \
  /tmp/entry-map.json --entry <exact-id-from-entries-or-aliases>
python3 docs/experiments/automatic-entry-candidates/probe.py item \
  docs/experiments/automatic-entry-candidates/fixture.json --route <exact-review-id>
```

Редирект и выбор назначения выполняет вызывающая сторона: не перенаправляйте
stdout поверх исходного экспорта. Сам скрипт открывает файлы только для чтения.
Вход и сериализованный выход CLI ограничены 8 MiB. Перед выдачей проверяется
UTF-8 размер **всего** JSON вместе с завершающим LF; слишком большой результат
отвергается до первого байта stdout, а не объявляется успешно созданной картой,
которую потом нельзя прочесть. Точные item-адреса ограничены 256 символами и
при превышении отвергаются, не ремонтируются.
Повторный build одинакового входа/конфига детерминирован и не зависит от порядка
items. Для точного оригинала `item` сохраняет исходные поля, а не восстанавливает
текст из карты. Код выхода 3 — точный вход/оригинал не найден, 2 — неверный или
недоступный вход. Ошибки не печатают тела памяти или сырой текст исключений.

## Предварительные критерии проверки

- Автоматически образуются ассоциации и entry без авторского cue.
- Одного времени или валентности недостаточно; основания не смешаны с
  семантическими причинными утверждениями.
- A—B—C не склеивается через одну транзитивность; допускаются общие узлы.
- Добавление третьего связанного узла раскрывается через прежний seed-адрес.
- Карта и оригиналы открываются отдельно в свежих процессах; неправильный адрес
  не ремонтируется и не заменяется похожим.
- Изменённый порядок входа даёт тот же результат, степень и вход ограничены,
  неизвестные данные не дорисовываются, ограничения явно указаны.
- Исходный экспорт и живая память остаются неизменными. Персональные корпуса и
  трассы не входят в публичный репозиторий.

Эти критерии проверяют формирование и повторное раскрытие зацепки. Они не
доказывают полезность лексической близости на всей истории, готовность энграммы,
эффективность напоминания, Dream-консолидацию или петлю усиления.
