# Выбранный проход от входа к оригиналам

Статус: второй проверяемый checkpoint экспериментальной ветки. Не production API метапоинтера, не автоматическое построение входов, не оценка fresh-agent/model efficacy.

## Зачем

После первой нейтральной пробы требовалось пройти реальную развилку: заметить компактный вход, явно раскрыть ограниченный фрагмент, отдельно выбрать оригиналы по нужной линии. Связанные ветви не должны сливаться в один рассказ, а открытие окрестности не должно считаться чтением оригиналов.

## Экспериментальный исполнимый шов

`selected_walk.py` намеренно остаётся здесь, вне `src/`:

- `expand_entry(entry, reader, depth=1, limit=4)` проверяет буквальный маршрут и пределы, вызывает только выбранное раскрытие и сохраняет частичность ответа;
- `open_selected(view, routes, reader, max_originals=3)` проверяет весь явный выбор до чтения первого оригинала; открывает только различные видимые exact routes;
- результаты копируются без переписывания смысловых полей;
- пустой выбор нормален; другой returned root/item не считается успешным проходом.

Вход — ручной эскиз `knows + route`, совместимый с первой пробой, не выбранная публичная схема хранения. Reader — существующий доверенный core/MCP, не произвольный недоверенный поставщик. Шов не заменяет валидацию core и не является самостоятельной security boundary.

## Проверки

Добавленные 20 проверок сначала завершились ожидаемым RED отсутствующего поведения, затем прошли. Вместе с четырьмя первыми проверками: **24 passed**. Полная изолированная Python-suite: **566 passed**. Каждый запуск сравнил live state/config hashes: `live_bytes_unchanged=True`.

Воспроизведение на нейтральных fixtures:

```sh
# Use disposable HOME/HERMES_HOME/XDG/MNEME_STATE_DIR/MNEME_CONFIG,
# and propagate that environment to subprocesses.

```

## Практический проход

В отдельном private evidence checkout сохранён executable driver и буквальные ответы настоящего MCP stdio, запущенного с временными HOME/XDG/config и копией реального состояния.

- Один авторский вход; два заранее явно выбранных родительским контуром вопроса/пути.
- В раскрытии: **3 узла, 2 авторские связи**, depth=1, limit=3.
- **`has_more=true` сохранён**, полнота истории не заявляется.
- Два пути открыли по два оригинала: **4 body reads, 3 уникальных оригинала**. Общий исходный оригинал открыт в обоих путях.
- Один путь проверяет основание архитектурной поправки, другой — отдельное продолжение исходного понимания. Исходное направление и ограничения доступны в оригиналах; direction/grounds связей возвращаются отдельно.
- Семантические источники временной копии и все живые state/config bytes остались неизменными. Явные reader repairs, если нужны, допустимы только внутри копии.
- Новых capture/review/connection записей, новой энграммы, изменений `src/`, production main или ingress/config не было.

Полные вопросы, личные тела и трассы не входят в публичный репозиторий.

## Что установлено — и что нет

Установлено, что авторский вход можно практически пройти до выбранных ветвей и оригиналов через существующий транспорт, без обязательного общего пересказа и без подмены originals навигационными claims.

Выбор сделала я, уже видевшая эту историю и ранее открывавшая оригиналы. Это не слепой эксперимент нового агента, не модельное доказательство распознавания, не контролируемый A/B и не проверка нативного Hermes ingress. Сам driver не удостоверяет смысловую удачность выбора: он сохраняет действие и возвращённые основания для отдельной оценки.

Не определены: persistence и публичная схема авторского метапоинтера, автоматическое формирование входов, пересмотр при изменениях и смысловом устаревании, новая политика bounded обхода. Известное скрытие нового `corrects` за старым бюджетом не исправлялось.

Следующий архитектурный выбор остаётся явным: достаточно ли существующего маршрута и авторского входа для следующего минимального продукта, или доказана потребность в сохраняемом метапоинтере. Графовые энграммы, забывание и экспорт не добавляются к этой пробе.
